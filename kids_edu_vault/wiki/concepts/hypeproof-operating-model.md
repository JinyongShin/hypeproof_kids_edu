# HypeProof 운영 모델 (How We Work)

> 출처 `/members/how-we-work` → [[members-portal-20260914-source]]
> 한 줄: **목적을 세우고, 기준으로 위임하고, 증거로 판단한다.**

> [!key-insight] 제품의 논리를 조직에 적용한 것이다
> *"주체성·판단·책임이라는 철학을 **우리 자신의 작업 방식에도** 적용합니다."*
> [[six-human-capabilities]]가 학습자에게 요구하는 것(Framing → Judgment → Orchestrate → Verify → Adapt → Ownership)과 아래 6단계 작업 흐름은 **같은 뼈대**다. 팀이 자기 제품의 첫 피험자다.

## 01 목적에서 증거까지 — 6단계

| # | 단계 | 묻는 질문 | 남길 기록 | 판단 주체 |
|---|---|---|---|---|
| 1 | **철학·미션** | 이 일이 인간의 주체성·판단·책임과 어떤 관계인가 | 정본 링크 + 검증할 가정 | 방향 변경은 해당 정본 책임자 |
| 2 | **Intent** | 누구의 어떤 문제를 왜, 어떤 변화를 원하는가 | 문제·대상·원하는 결과·**하지 않을 일** | 제안자 + 도메인 책임자 |
| 3 | **요구사항·성공 기준** | 무엇이 충족돼야 성공이며 어떤 제약을 지키는가 | 성공·실패 조건, 확인 방법 | 담당자 구체화 → 도메인 책임자 판단 |
| 4 | **설계·위임** | 어떤 방법을 택하고 AI에 어디까지 맡기는가 | 설계 근거·대안, 역할·권한, **중지 조건** | 담당자. ⚠️ **이슈 배정 ≠ 승인권 위임** |
| 5 | **구현·검증** | 요구사항대로 동작하며, **원래 원했던 변화도** 확인했는가 | 요구사항별 테스트 + 실제 관찰 + 한계 | 담당자 제출 → 리뷰어·권한자 판단 |
| 6 | **증거·학습** | 무엇을 배웠고 어떤 기준·가정을 바꿔야 하는가 | 관찰 원자료·출처, **버전이 있는 해석**, 반론 | 기준 변경은 책임자 검토 후 다음 Intent로 |

작업 크기에 맞게 기록하되 **연결은 유지**한다. 작은 수정은 기존 기준을 참조하고, 목적·기준이 바뀌면 정본과 영향받는 연결을 함께 검토한다.

> **반복되는 경고**: *"웹 검증 통과를 실제 앱 체험이나 인간 성장의 증거로 확대하지 않는다."* 이 문장의 변주가 문서 전체에 열 번 넘게 나온다. 산출물 완성 ≠ 목적 달성 ≠ 학습 효과.

## 02 조직 형태 — 기여 기반

> **고정 급여를 전제로 한 상근 조직이 아니다.** 업무량을 똑같이 나누기보다, **[[jay-lee|Jay]]가 사업의 위험과 실행 공백을 맡고** 멤버는 **수락한 범위·기간·시간 안에서** 결과를 만든다.

- 각 제품은 Jay + 제품 리드가 함께 이끌되 **결정 범위를 나눈다.** Jay = 방향·자원·주요 약속·최종 판단 / 제품 리드 = 고객 문제 정리·우선순위 제안·실행 조율·주간 진행 공유
- **담당자가 맡지 않은 일은 자동으로 그 사람 책임이 되지 않는다**
- **역할명이 무제한 책임을 뜻하지 않는다.** 리드 타이틀만으로 다른 멤버의 시간을 배정할 수 없다
- 기여가 커지면 **권한과 보상도 함께 재검토**

### 제품 리드는 제안할 수 있다

개발자일 필요 없음. **제안 → Jay와 범위 합의 → 4주 실행 → 지속·조정·인계 결정.**
제안할 것: 맡고 싶은 이유 / 고객 문제 / **첫 4주 산출물과 검증 기준**.

## 03 무엇을 만들고 누가 책임지나 — 4개 층

혼동을 막기 위해 층을 명시적으로 갈랐다. **강의·워크숍·캠프는 진행 형식이지 제품이 아니다.**

| 층 | 내용 | 담당 |
|---|---|---|
| **01 제품** | [[hypeproof-studio]] · [[chalk]] · [[sediment]] | Studio 리드 **[[jiwoong-kim|지웅]]** / Chalk·Sediment는 Jay 총괄 (리드 제안 가능) |
| **02 공통 실행 기반** | **Harness / AI Crew** — Scout·Compass·Forge·Lens·Keeper + 공용 스킬 | Jay 공용 방향 / **[[jesse-kim|광현]]** 품질·운영 |
| **03 교육 프로그램** | 창업교육 · 홈페이지 만들기 강의 | **[[jiwoong-kim|지웅]]** / **[[jehyeong|제형]]** |
| **04 교육 운영 도구** | 교육 결과 정리 파이프라인 (수집·갤러리·리포트·인계) | 프로그램 담당자가 범위 합의 |

```
공통 실행 기반 → 제품 개발·프로그램 준비 지원
제품 → 교육 프로그램에서 활용 → 실제 고객·학습자 결과
교육 운영 도구 → 결과·근거 정리 → 제품 개선 요구
제품 리드 → 근거 검토 → 다음 로드맵
```

> ⚠️ *"라인업에 포함됐다고 출시·판매 중이라는 뜻은 아니다."* · *"결과물 보유만으로 학습 효과를 입증하지 않는다."*

## 04 인간 책임자 9역할

배정과 KPI는 [[roles-kpi-proposal-20260914]]로 분리했다 — **2026-09-14 기준 제안이지 합의가 아니다.**

전략 · 제품 · 고객·사업 · 교육·연구 · 개발 · 품질·운영 · 브랜드·콘텐츠 · 법무·IP · 사업관리

**RACI 19행**이 단계별로 A(최종 책임) 하나씩을 박아 둔다. 겸임은 가능하지만 **결정별 A는 한 명**. 역할 표가 기존 리뷰·배포 승인권을 우회시키지 않는다.

## 05 주간 실행 루프

| 시점 | 단계 | 내용 |
|---|---|---|
| **월 저녁** | Weekly 미팅 | 전원. 회의록 자동 기록 → 결정·액션이 그 자리에서 남음 |
| **화** | 회의록 분해 | AI가 회의록을 **각 레포의 현재 상태와 대조**해 액션을 매핑. 진행 중인 일·중복·어긋난 전제가 여기서 걸러짐 |
| **화** | GitHub 이슈 발행 | Intent·요구사항에 연결. 배경·성공 기준·담당·**다음 회의 전 ETA** |
| **주중** | 실행 | 반복 개선은 자율주행 루프에. 사람 시간은 판단과 피드백에 |
| **주중~주말** | 산출물 축적 | members 포털 게시 + [[sediment]] 인제스트 |
| **다음 월** | 리뷰 | 완료/미완료 **+ 목적 달성의 증거·반론·남은 불확실성** |

레포 3개: **hypeprooflab**(브랜드·철학·사업·포털) · **hypeproof-studio**(제품 엔지니어링) · **sediment**(증거·메모리 층). 공통 프로세스는 **hypeproof-harness**.

## 06 여섯 원칙

| 원칙 | 내용 |
|---|---|
| **Issue-first** | 실행할 가치가 있으면 이슈가 된다. **기록이 없다고 미실행으로 단정하지 않고 담당자에게 확인**한다 |
| **ETA Rule** | ETA 없는 이슈는 발행되지 않는다. 일주일을 넘기면 **"월요일까지의 1차 산출물"**로 쪼갠다 |
| **Direct, don't type** | 사람은 방향, AI는 실행. 목적 설정·위임 경계·검증·책임까지가 우리 일 |
| **Evidence** | **관찰 원자료와 해석을 구분하고 해석의 버전을 기록**한다. 저장된 산출물만으로 목적 달성을 주장하지 않는다 |
| **Single source** | **포털에 정본을 새로 만들지 않는다.** 포털은 읽기 창구다 |
| **Harnessed** | 루프 자체도 자동 검증. 단 **목적의 타당성·요구사항의 충분성·사람의 승인은 대신하지 않는다** |

## 07 Source of Truth

| 층 | 정본 | 갱신 |
|---|---|---|
| 실행 · 주간 | `GitHub 이슈 + cycle 라벨` | 화요일 회의록 분해 (weekly-loop) |
| 이벤트 | `GitHub 마일스톤 + 이슈 연결` | 분해 시 생성 |
| 상태 | `이슈 활동 (PR·코멘트·이월)` | 자동 추론 |
| 전략 · 테마 | `roadmap.strategy.json` | 드물게, 사람이 PR로 |

테마↔이슈는 라벨 `theme:<id>`로 연결. 파생 데이터(`weekly.json`·`roadmap.json`)는 **절대 손으로 고치지 않는다.**

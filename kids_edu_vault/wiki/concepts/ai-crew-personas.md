# AI Crew — 5 페르소나와 위임 등급

> 출처 `/members/how-we-work` → [[members-portal-20260914-source]]
> 구현 정본: **hypeproof-harness**의 `skills/hypeproof-*`

> [!important] 스킬 존재 ≠ 자동 실행
> *"페르소나는 맡은 관점이고, 스킬은 반복할 절차입니다. **스킬 등록만으로 자동화되지는 않습니다.**"*
> 다섯 모두 **공용 스킬은 구현됐고 자동 실행 연결은 전부 `전`**이다. 앱 연결·스케줄 실행·팀 배포도 아직이다.

## 다섯 페르소나

| 페르소나 | 역할 | 한 마디 | 남기는 결과 | 인간 책임자 |
|---|---|---|---|---|
| **Scout** | Researcher | *"그 주장을 뒷받침하는 근거와 반대 증거는?"* | 근거 / 가설 / **모르는 점** | [[bongho-tae|봉호]] 연구 해석 · [[jiwoong-kim|지웅]]·[[jehyeong|제형]] 고객 맥락 |
| **Compass** | Planner | *"누구의 어떤 결과를 바꾸려는지부터."* | 범위 / 인수 기준 / 선택지 | [[jay-lee|Jay]] 제품 방향 · [[jiwoong-kim|지웅]] Studio 우선순위 |
| **Forge** | Builder | *"검토하고 실행해볼 수 있는 형태로."* | 결과물 / 변경 내역 / 자체 테스트 | [[jinyong-shin|진용]] 기술 · [[bongho-tae|봉호]]·[[jehyeong|제형]] 교육 · Jay 브랜드 |
| **Lens** | Verifier | *"잘된다는 설명보다 실제 결과를."* | **통과 / 실패 / 미검증** / 남은 위험 | [[jesse-kim|광현]] 품질 · [[minhan-cho|민한]] 법무 · Jay 출시 |
| **Keeper** | Context Steward | *"지금도 유효한 결정인지, 다음 사람이 이어갈 수 있는지."* | 재확인 대상 / 충돌 근거 / 갱신안 / 인계 | [[jesse-kim|광현]] 정리 운영 · 각 영역 책임자 |

### 각 페르소나에 박힌 금지

설계의 핵심은 능력이 아니라 **월권 차단**이다.

- **Scout** — 모르는 것을 사실로 채우지 않는다. **고객 한 명의 반응을 시장 전체로 확대하지 않는다**
- **Compass** — 계획은 만들되 **우선순위와 고객 약속을 임의로 확정하지 않는다**
- **Forge** — **자체 테스트를 실제 고객 성과로 보고하지 않는다**
- **Lens** — **기준을 낮춰 통과시키거나 출시를 대신 승인하지 않는다**
- **Keeper** — **오래됐다는 이유로 지우지 않는다.** 원문을 보존하고 정본 변경은 담당자에게 넘긴다

## 위임 3등급

| 등급 | 대상 | 규칙 |
|---|---|---|
| **자동 실행** | 승인된 입력·범위 안의 조사·초안·테스트·상태 확인 | 실행 기록과 증거를 남긴다 |
| **검토 후 실행** | **고객 발송 · 공개 콘텐츠 · 출시** | AI는 검토 가능한 결과를 만들고 **권한 있는 사람이 승인** |
| **인간 주도** | **고객 관계 · 협상 · 방향 · 자원 배분 · 최종 약속** | AI가 가능해도 인간이 책임지고 결정 |

**인계 조건** — 근거 부족 / 요구 충돌 / 권한 밖 행동 / 검증 실패. AI는 **멈춘 이유·증거·선택지**를 책임자에게 넘긴다.

**스킬 필수 항목 7개** — 입력 / 절차 / 산출물 / 완료 기준 / 허용 권한 / 인계 조건 / 기록 위치.
> **제작과 검증은 분리하고, AI 검증을 실제 고객·학습 효과의 증거로 대신하지 않는다.**

## KPI

| 대상 | 지표 |
|---|---|
| AI Crew 공통 | 기준 통과 / 검증 건수 · **인간 재작업 / 처리 건수와 원인** · 인간 판단 대기 시간 |
| Keeper | 재확인 기한 지난 활성 기록 수 · 미해결 충돌 수 · 담당자 확인 대기 시간 |

> **처리 건수를 늘리는 목표를 두지 않는다.** Keeper는 **삭제량을 성과로 삼지 않는다.**

## 우리 볼트와 겹치는 곳

> [!key-insight] Keeper는 이 볼트가 이미 하는 일이다
> Keeper의 직무(기한·상태·명시적 값 충돌을 **읽기 전용 도구로 점검**, 원문 보존, 정본 교체는 사람이 판단)는 우리 `wiki-lint` + `hot`/`log` 규약과 거의 같다.
> 우리 쪽이 더 나아간 부분: **`[!contradiction]` 콜아웃으로 충돌을 양쪽 페이지에 남기는 관행.** Keeper 명세에는 충돌 *탐지*만 있고 *기록 형식*이 없다.
> 우리 쪽이 뒤진 부분: **재확인 기한(TTL)이 없다.** Keeper KPI의 "재확인 기한 지난 활성 기록 수"에 대응하는 필드가 우리 frontmatter에 없다.

[[subagent-team-structure]]의 6개 에이전트(architect·implementer·tester·reviewer·wiki-ingest·wiki-lint)와 이 5개는 **다른 층**이다 — 우리 것은 이 레포 작업용, AI Crew는 조직 공통. ⚠️ 통합·정렬 여부 미정.

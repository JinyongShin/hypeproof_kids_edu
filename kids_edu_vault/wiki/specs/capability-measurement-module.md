# 역량 측정 모듈 (measurement-core)

> 출처 [[members-portal-20260914-source]] · Epic [hypeproof-studio#1020]
> 한 줄: **관찰 기능을 Studio에서 떼어내, Studio·Claude Code·Codex가 같은 기준을 쓰게 한다.**

## 왜 분리하나

관찰 기능은 원래 [[hypeproof-studio]] 안에 있었다. 그런데 **실제 제품 작업은 Studio뿐 아니라 Claude Code와 Codex에서도 일어난다.** 학습자만 관찰 대상인 게 아니라 **우리 자신의 업무**가 대상이 된 것이다.

> 9/14 사전자료 §1: *"우리가 중요하다고 설명하는 기준을 **우리 자신의 일에서** 어떻게 활용할지부터 확인해야 하는 상태."*

| 지금 확인할 수 있는 것 | 아직 답하기 어려운 것 |
|---|---|
| 코드·문서·PR 등 만들어진 결과물 | 사람이 **어떤 목적과 기준으로** 그 결과를 선택했는가 |
| AI 대화와 도구 실행 기록 | **사람이 판단한 부분과 AI에 맡긴 부분**은 무엇인가 |
| 테스트와 검증 결과 | 사람이 무엇을 확인했고 **그 결과로 판단을 어떻게 바꿨는가** |
| 기존 수업 기록과 관찰 기능 | **일상 업무에서도** 관찰·검토·개선이 반복되는가 |

## 사용 흐름

```
작업 목적·행동 기록
  → 근거를 인용한 역량 해석 ([[six-human-capabilities]])
  → 본인 검토·정정
  → 선택한 기록의 로컬 제출
  → 다음 작업에서 개선점 적용·확인
```

기록 단위 5요소: **작업 목적 / 행동과 원근거 / 해석(원문 인용 + 해석 버전) / 본인 검토 / 후속 확인.**
본인 검토에는 **확인·정정·이견·공유 제외·보류**가 들어간다 — 관찰이 틀렸으면 **본인이 정정할 수 있다.**

### ⛔ 완료로 주장하지 않는 것 (문서가 직접 열거)

- Studio · Claude Code · Codex **세 환경의 실제 연결과 사용**
- [[jay-lee|Jay]]의 기록 → 검토 → 제출 → 다음 작업 개선 **전체 흐름**
- **수치 점수화와 역량 측정의 타당성**
- **학습·업무 역량의 성장 효과**

## 첫 사용자는 Jay

실제 작업 **한 건**에서 기록·검토·제출을 진행하고 **다음 작업에서 개선점 적용 여부까지** 확인한다. 그 결과로 기록 부담·관찰 기준·연결 기능을 수정한 뒤 범위를 넓힌다.
**전 멤버 강제 적용은 이번 개발 범위가 아니다.**

### 첫 과제의 지표

- 기록한 실제 작업 수
- 검토한 해석 수와 **정정·이견·보류 건수**
- 로컬 접수까지 확인한 제출 작업 수
- 다음 작업에서 개선을 시도한 건수와 결과 확인 여부

> **정정·이견이 많다는 이유로 낮은 성과로 해석하지 않는다.** 관찰 기준과 제품을 개선하는 자료로 쓴다.

## 왜 이게 중요한가

[[record-issuance-model]]이 팔려면 **"기록"이 실제로 판단을 담아야** 한다. 9/6에 [[jiwoong-kim]]이 제시한 대시보드 매트릭(제작자·사용자·이번 주 사용자·마지막 갱신)은 전부 **활동량**이고, [[six-human-capabilities]]가 "이것만으로는 부족"으로 기각한 종류다.
이 모듈이 그 간극을 메우는 물건이다. **다만 아직 실사용 0건이다.**

- ⚠️ **여섯 역량은 확정이 아니다.** #1049 본문: 여섯 역량(Framing/Judgment/Orchestrate/Verify/Adapt/Ownership)은 *"versioned candidate definitions, open to future revision"*이며 작업명 "HypeProof Capability Evidence / HypeProof 역량 관찰"도 **확정 리브랜드가 아니라고 명시**한다. 7 AI Native Assets와의 관계는 `미확인`. → [[six-human-capabilities]]

> [!warning] 관문이 이 모듈을 기다릴 수는 없다
> [[chalk-requirements]] CR-CAP-08(=`HC-08`)이 **"연구의 최소 construct audit를 통과한 정의만 새 측정 구현에 쓴다"**고 걸어 둔다. 후보 역량 6종의 타당성 검증이 끝나기 전에는 **역량 기반 합격선을 세울 수 없다.**
> 따라서 [[chalk]]의 관문이 지금 세울 수 있는 축은 역량 판정이 아니라 **수업 설계·운영 계약의 준수**다. 이 구분은 라인업 정본의 문구와도 같다 — *관문이 판정하는 것은 계약 준수이고 학습자 역량 해석과 구분한다*.

### 🆕 `HAIN7` 폐지 (2026-09-15) — `HC-09` + `MR-01~04`

제품 요구사항(`capability-model-contract.md`의 `HC-09`)과 lab 제품 문서(`measurement-retirement.md`의 `MR-01~04`)에 **동시에** 들어왔다.

- 새 측정과 권장 에이전트 흐름에서 **`HAIN7`은 폐지**. 진입점은 **6역량 워크벤치와 그 버전 있는 방법론**
- 과거 scorer·rubric·결과는 **명시적으로 선택한 과거 재생/내보내기에서만** 열린다
- ★ **7→6 변환이 일어나지 않는다.** 과거 기록은 **당시 7축 정의를 유지**하며 6축 점수가 되지 않고, 원자료는 덮어쓰지 않으며 과거 방법론 판은 **바이트 보존**해 보관용으로 표시한다 (`MR-02`·`MR-03`)
- 이것이 [[six-human-capabilities]]의 "이름 통일이 아니라 버전으로 푼다"는 판정을 **정본 수준에서 집행한 첫 조항**이다. 측정 축 분열이 한 겹 좁혀졌지만 — **두 층이 언제 합쳐지는지는 여전히 미결**이고 6역량이 7보다 우수하다는 검증은 없다

# Chalk 완성형 제안 (2026-09-14)

### 문서 구성 (9장)

`00` 요약 → `01` Chalk란 무엇인가 → `02` Jay 요구사항 → `03` JY 사전 조사·제안 → `04` 겹치는 지점 → `05` 충돌·공백 → `06` 해결 제안 → `07` 제안하는 완성형 → `08` 단계와 미결

4장과 5장은 **좌우 대조 패널**이다 — 왼쪽 Jay 요구사항, 오른쪽 JY 사전 조사, 가운데가 연결선(4장)이거나 충돌 표시(5장).

## 핵심 주장 — Chalk는 관문이다

> **Chalk는 만드는 도구이기 전에 통과시키는 관문이다.**
> 강의는 무엇으로 만들어도 된다. 다만 학생에게 도달하려면 Chalk를 통과해야 한다.

[[chalk]]의 기존 정의("입력하면 강의안을 만들어 주는 프레임워크")를 **버리지 않고 뒤로 미룬다.** 생성기는 재료가 쌓여야 작동하고 재료는 수업이 실제로 돌아야 쌓이므로, **관문 → 수업 축적 → 생성기** 순서로 간다.

관문 개념 자체는 새것이 아니다. [[jinyong-shin]]이 2026-08-31 회의에서 이미 말한 **게이트웨이 역할**("초크로 만들었으면 HypeProof 교육관에 맞는 교육일 것"을 보증)이며, 이 문서는 그 발언을 **확정(freeze) 시점**이라는 구현 가능한 자리에 연결한 것이다.

### 왜 관문인가

- **편의성 경쟁을 피한다.** "범용 AI 도구보다 편해야 한다"는 이기기 어렵다. 관문으로 서면 강사는 쓰던 도구를 계속 쓰고 **우리가 쥐는 것은 전달 권한**이다
- **보증이 성립한다.** 외부 강사에게 우리 이름을 빌려 줄 수 있는 유일한 근거
- **강사 수와 품질을 따로 조절할 수 있다.** 진입 마찰은 낮추고 관문만 조인다 → 지웅 KPI ①(연간 캠프 횟수)

## 조사에서 드러난 것

### ★ 교육 원칙의 절반이 이미 제품 요구사항에 있다

서로 참조한 적 없는 두 자료에서 **8쌍이 같은 말**을 하고 있다.

| JY 자산 | 요구사항 | |
|---|---|---|
| 합친 점수 금지 | `DES-12` `ADM-09` | "프롬프트 수를 능력 점수로 표현하지 않는다" |
| 관찰됨/미관찰이지 미달 아님 | `HC-05` | "빈 증거를 0점으로 채우지 않는다" |
| **대행 금지** | **`HC-04`** | "AI가 작성한 문장을 학습자 독립 수행 증거로 저장하지 않는다" — **판단 근거까지 일치** |
| 기록은 관찰이지 진단 아님 | `HC-03` `HC-06` | 원자료 불변 + 해석을 버전으로 분리 |
| 근거 등급 | `HC-08` | "연구의 최소 검증을 통과한 정의만" |
| 도움 줄이기 단계 | `EDU-05` `EDU-02` | 직접/도움받아/위임으로 자립 범위 정리 |
| 증거는 제3자가 볼 수 있는 물건 | `ADM-06` `EDU-03` | "결과물 제출만으로 합격시키지 않는다" |
| 통과는 검사한 버전에 붙는다 | `VER-02` | 변경 시 합격 무효화 |

**함의**: 교육 원칙을 제품에 "이식"하는 것이 아니라 **두 어휘를 대응표로 맞추는 일**이다. `HC-01`이 이름 변경을 금지하므로 **통일하지 않고 매핑만 한다.**

반대 방향도 하나 있다 — `HC-07`("비용·토큰량은 역량 등급이 아니다", **못 한 것과 안 한 것을 구분**)은 JY 측정 축에 없던 조항이라 가져와야 한다.

### ★ 양쪽이 똑같이 비어 있다

- 제품: 검수된 실행 템플릿 **0개**라 독립 강의 개설이 실제로는 안 열린다
- JY 자산: 수업 부품 **0건**, 자동 검사 **0/12**

두 저장소가 서로 모른 채 **"기계는 다 만들었고 부품이 없다"**는 같은 상태에 도달했다. 같은 미결의 두 얼굴 — *무엇을 부품으로 인정할지를 아무도 정하지 않았다.*

### ★ Chalk 요구사항 문서의 범위는 치과 성인 과정이다

`docs/requirements/chalk-authoring.md` 첫 줄: **"범위: 치과의사 대상 정적 HTML/CSS/JavaScript 홈페이지 수업."** 53개 항목 전부가 성인 전문직 기준으로 쓰였고 아동·청소년을 전제한 적이 없다. → **교육 원칙 2층 분리**가 새 구조 도입이 아니라 현상 기술이 되는 근거.

### ★ 확정에는 내용 검사가 없다 (문서의 자기 진술)

> Freezing stores an **unverified** snapshot, not a deployable class.
> Rehearsal evidence, settings pins and activation **remain planned**.

차단 장치 자체는 제품 전반에 있다 — `VER-02` 합격 무효화, `US-14` 승격 차단, `opening_blocked_by`, fail-closed 기본값, 좁히기만 허용. **다만 전부 형식·권한 검사이고 내용 검사는 없다.**

### `CLS-04`는 아직 구현 전이다

"학생 허용 후 강사가 수정" — 우선순위 P1, 연결 테스트 0건, 「첫 구현 경계」가 *"원격 수정은 후속이다"*로 유예. **지금이 가장 싸게 고칠 수 있는 시점.**

| 충돌 3 | **수업 단위로 출발 + `CH-05`(제작 기록에서 초안 생성)를 두 번째 경로로** ⚠️판단 필요 · 대안: 부품 단위 선행 |

## 시스템 구성 7층

```
강사 · 웹 (Chalk 워크스페이스)        일부 구현
      ↕
AI 보조                              신설  ← 가장 비어 있는 칸
      ↑ 읽기 전용
지식 자산                            대부분 미구축  ← 가장 비어 있는 칸
      ↓
관문 (완전성 + 교육 원칙 + 순서 제약)  자리만 있음
      ↓ 불변 확정본
브릿지 · Service (자격 발급·권한)      구현됨
      ↓
Studio · 학생                        구현됨
      ↓
되먹임 → 지식 자산
```

**저장소를 어디 두든 강사가 만나는 것은 웹 페이지 하나**여야 한다. 요구사항도 이미 그렇게 요구한다 — *"Studio에서 접근해도 Chalk 웹 화면의 모바일 접근성을 유지한다."* 내장 화면은 진입 경로이고 웹 화면이 정본.

### 수업 자산화 경로

`실행 → 검수(귀속 판정 + 원칙 검사 + 학생 데이터 제거) → 등록 → 다른 강사가 복제·참고 → 설계 중 "비슷한 수업 있음" 알림`

**제품에 이미 자리가 있다** — 독립 강의 개설이 "검수를 통과한 실행 템플릿만" 묶도록 만들어져 있고 등록된 것이 0개일 뿐이다. 3장의 부품 0건과 같은 구멍이지만, **이 경로는 부품을 새로 만들지 않아도 채워진다.**

이것이 충돌 3 판정을 강화한다 — 검수된 수업을 다른 강사가 가져다 쓰면 **같은 수업 하나가 여러 강사에게 곱해지므로**, 부품 단위가 주려던 배수 효과를 수업 단위에서도 얻는다.

## 3단계

| 단계 | 내용 |
|---|---|
| 1 · ~10월 | 관문 골격 + **학생 조건 리허설**. 리허설은 외부 강사 검증의 전제이며, 요구사항 「첫 구현 경계」에 이미 들어 있다 |
| 2 · 11~12월 | 강사 금지 항목 + 강사 수정의 증거 분리 + 저작 귀속 필드. **첫 외부 강사 운영 1회** 실측 |
| 3 · 2027-01 | `CH-05` 생성 경로 + 피드백→다음 설계 루프. 부품 단위 재판단 |

**7장의 구성은 완성형 그림이고 3개월은 그중 일부만 짓는다.** AI 보조와 공유 자산은 재료가 쌓인 뒤에 붙인다.

## 팀에 요청하는 결정 4개

1. **Chalk를 관문으로 정의하는 데 동의하는가** — 동의 시 "강의안을 만들어 주는 물건"은 3단계로
2. **교육 원칙을 공통 / 대상별 2층으로 나눠도 되는가**
3. **재사용 단위를 수업으로 두고 시작해도 되는가**
4. **수업 설계 형식의 소유자를 Service로 확정할 수 있는가** — 저장소 분리와 3개월 순서가 여기 걸림
